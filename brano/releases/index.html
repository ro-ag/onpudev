Release notes

What changed in each Brano release, newest first. Get the current release from the download page.

0.7.0-beta.6 Latest 2026-11-18

Added

  • Help ▸ Brano Help opens the online user help (English or Spanish, following the interface language).
  • Release workflow mirrors the signed macOS DMG and the Linux archive to https://downloads.onpu.dev/brano/ (Cloudflare R2), because this repository's GitHub Releases are private. Windows is distributed through the Microsoft Store only. The step is skipped until the R2 credentials are configured.

Changed

  • macOS: the bundle identifier is now dev.onpu.brano (was com.roag.brano), matching the Onpu identity used on Windows. macOS treats the app as new, so it asks again for permissions such as microphone access; projects and settings are unaffected.

0.7.0-beta.5 2026-11-03

Added

  • Windows: MSIX package manifest and packaging script for Microsoft Store distribution (packaging/windows/msix, tools/package-windows-msix.ps1). The package is unsigned and carries the Partner Center identity of the reserved app name (publisher Onpu, Store ID 9N48C2CH9B61); the Store signs it on submission.

Changed

  • Plug-in editor windows and the detached Maestro window no longer get a taskbar or Dock entry of their own. Editor workers (native-rack 0.11.0) attach their window to Brano's main window: an owned window on Windows, a transient window with skip-taskbar hints on X11, and stacked directly above Brano on macOS. The plug-in still runs in its own crash-contained process. The detached Maestro window is owned by the main window on Windows and is a transient, skip-taskbar utility window of it on X11.

Fixed

  • Windows: brano.exe embeds a PerMonitorV2 DPI-aware application manifest. The executable had no resource section, so the Windows App Certification Kit's High-DPI test reported the app as not DPI aware even though winit requests per-monitor awareness at startup.

0.7.0-beta.4 2026-10-26

Changed

  • Update native-score to v0.7.1 and croma-core to 1.4.0 for arpeggio alignment, revised engraving rules, ABC text decoding, and parser fixes. Saved audio freezes from the previous compiler versions are invalidated.
  • Raise the minimum Rust version to 1.98 and pin development and build workflows to Rust 1.98.1, as required by native-score.
  • Declare Brano as proprietary software distributed in binary form only. The workspace manifest now points at the new LICENSE end user agreement instead of claiming LGPL-3.0-or-later, and THIRD_PARTY_LICENSES collects the license texts of every open source crate compiled into the binary, generated by tools/third_party_licenses.py.

Security

  • Update dependencies with published RustSec advisories: rustls 0.23.46, rustls-webpki 0.103.16, webpki-roots 1.0.11, rtrb 0.3.6, crossbeam-epoch 0.9.21, webbrowser 1.2.5, zip 9.1.2, and zstd 0.14.3 (zstd-safe 8.2.0, zstd-sys 2.1.2). Archive entries whose names fail zip's validation are now skipped when importing compressed MusicXML or reading VirtuosoNet checkpoints.

Fixed

  • Perform cards expand to contain wrapped labels and the preset button, including the Spanish Swing amount label at compact window sizes.

0.5.0-beta.1 2026-09-27

Added

  • Maestro settings: per-model advanced request parameters. A JSON object, saved per provider and model, is merged into every request (a key sets a field, null removes one), so provider options such as reasoning_effort or top_p can be set without a new build.
  • Xiaomi MiMo web search, streamed: cited pages appear under the reply and the billed search count comes from MiMo's own usage report. Enable the Web Search plugin in the MiMo console first; search rounds run without deep thinking.
  • Frame pacing follows the display: on macOS 14 and newer a native display link ties frames to the screen's refresh at a steady rate (at most 120 Hz) while Brano animates; elsewhere frames use the monitor's refresh rate. BRANO_DEBUG_FRAME_PACER=1 logs the clock in use.

Changed

  • Maestro's live reasoning renders inline markdown (bold, code, headings, bullets, code blocks) instead of literal ** and backticks, and scrolls through its newest 64,000 characters instead of a 1,200-character tail.
  • Reasoning models get room to finish: MiMo defaults to 131,072 reply tokens (sent as max_completion_tokens, its documented field), GLM and Kimi to 65,536. Configs still on the old 16,384 default are raised on load; the reply-token slider reaches 131,072.

Fixed

  • The screen no longer flickers while Brano is maximized on variable-refresh displays (such as 240 Hz OLED monitors).
  • Musical accidentals (♭ ♮ ♯ 𝄪 𝄫) render instead of empty boxes.
  • Arithmetic such as 3*4=12 in Maestro's reasoning keeps its asterisks.

0.4.0-beta.1 2026-09-26

Added

  • Instrument banks: a curated multitimbral VST3 host (Kontakt, EastWest Opus, HALion, ARIA Player) plays several parts from one plug-in instance, each on its own MIDI channel. Plug-ins that host a single instrument (Komplete Kontrol, pianos, synths) are not offered as banks; a non-curated plug-in can be marked "Treat as bank (advanced)" in the Plug-in Manager.
  • Every track header and mixer strip shows its bank and MIDI channel ("B1 · Ch 3", "GM · Ch 1"). A channel that differs from the score shows as "Ch 3 ≠5"; clashes and faulted banks are marked in red.
  • Assign a part to a bank, pick its channel, or remove it from the track chip or the mixer readout. The next free channel is suggested, starting from the score's own channel.
  • View ▸ Banks…: a 16-channel table per bank (channel, part, score channel, output, instrument label, status) with swap, rename and an explicit Delete Bank; parked banks keep their plug-in state when their parts leave and can be restored; Group into bank assigns several parts at once and splits beyond 16 parts into new instances.
  • Bank templates: save a bank's wiring, optionally with its loaded instruments, and apply it to any score with a preview that matches parts by name, instrument and score channel.
  • Shared main output: a bank can play through one mixer strip; member faders are inactive and muting a member holds back its notes only.
  • Channel, member and output changes re-route the running plug-in instead of reopening it, so Kontakt no longer reloads its libraries.
  • Maestro sees how parts are wired and proposes bank or channel changes on a confirm card, only when the user asks; its outcome rows report what score edits did to the wiring.
  • Maestro providers: Z.ai (GLM 5.3) and Moonshot (Kimi K3), both with 1M-token context, on pay-per-token API keys.
  • Maestro reply language: Match UI (default), Match my message, English or Español. Lyrics, titles and ABC are never translated.
  • Maestro can change a part's General MIDI instrument when asked.
  • Optional web search (Anthropic, Z.ai) and image input (Anthropic, Kimi K3, GLM 5.3 Flash), both off until enabled in Maestro settings. Image metadata such as location is removed before sending.
  • History: restore any earlier revision of the score.

Changed

  • Playback that reaches the end of the score now stops. It used to stay in Playing, which kept editing locked, held back Maestro's changes and kept the window repainting (high idle CPU).
  • Each Maestro turn reports what happened to the score: applied, waiting for playback to stop, not applied (with the reason) or no changes.
  • Maestro chat wraps at the pane width; tables fit the bubble and no longer change width while scrolling.

Fixed

  • Losing the audio device or having its sample rate changed by another app stops playback with a notice instead of freezing in Playing. Brano reconnects only to the same device settings and never discards frozen audio on its own.
  • Plug-in instruments kept sample-accurate timing after audio rebuilds, plug-in swaps and missed audio blocks; notes previously drifted late or early for the rest of the session.
  • Stop no longer restarts playback.
  • Kimi requests failed because a temperature was always sent.
  • History rows added while a save was in progress were dropped.

0.3.0-beta.1 2026-09-25

Added

  • AI Pianist playback style: VirtuosoNet (Jeong et al., ISMIR 2019; first at RenCon 2025), ported to pure Rust, plays the piano parts with learned timing, dynamics and pedalling and sets the tempo the other parts follow. New sessions start on it when its model is installed.
  • Settings ▸ Add-ons: optional third-party components Brano downloads on request instead of shipping. The AI Pianist model is fetched from its authors' Hugging Face page after a third-party notice, checked by SHA-256, converted on the machine and installed in the data folder; Remove deletes it.
  • A performance rule engine after the KTH rule system: phrases found on the melody, a two-level phrase arch, duration contrast, phrase-end breaths, leap and repetition articulation, chord voicing, melody lead, jazz tonguing and lay-back, stepwise inégales, and written tempo words (rit., accel., a tempo, fermata approach) and cresc./dim. text.
  • MIDI clean-up on every render: duplicate unisons, extra notes in voices and winds, hanging and empty notes, pedals and bends left on, and piano pedals on other instruments are removed, with a report.
  • Instrument categories in the plug-in pickers: instruments are listed under Piano, Keys, Synth, Sampler, Drums, Orchestral, Strings, Brass, Woodwinds, Voices, World or Other, and the Plug-in Manager shows vendor, format, version and category.
  • Output bus names in rack routing ("TG3 Front", "TG3 Rear"), read from the plug-in when it opens.
  • A factory preset browser per track: the vendor presets installed under the standard Presets folders, with search and a folder tree, reachable from the track's sound menu and the Instruments dialog. The loaded preset is shown on the track and marked "(edited)" once you change the sound.
  • Curated default presets for a fresh assignment: The Grand 3 starts on Model D ▸ Player ▸ Nicely EQed.
  • Plug-ins are told their track's name and colour when they open and again when the part is renamed or recoloured; a shared rack is told the rack's name.

Changed

  • Default plays in strict time; expression lives in dynamics, voicing, balance and articulation. Written tempo changes still play.
  • A melody marked far above its accompaniment (a singer's f over a pp piano) is balanced from both sides, and CC11 expression no longer attenuates a part a second time once velocity carries its dynamics.
  • The bundled Fauré demo drops its Italian verse and hidden rhythm variants (the French line only) and its voice uses a voice sound instead of Oboe.

Fixed

  • Voice and piano stay together under the AI Pianist and every rule style.
  • Steinberg The Grand 3 now sounds during playback without opening its editor (native-rack v0.10.1 keeps the plug-in worker's run loop serviced while idle). Exporting or freezing it still renders silence.
  • The default mix of a multi-output instrument sums its main and default-active buses, the same live, in export and in freeze.
  • Running the test suite no longer rewrites the recent-files list or any other settings file.

0.1.0-beta.15 2026-09-16

Native interface repairs, safer plug-in discovery, and session/playback reliability.

Fixed

  • Avoid initializing effect DSP or editor views during discovery when supported VST3 metadata is available, preventing the observed UAD sample-rate alert cascade. Add Stop scan without quarantining the cancelled plug-in.
  • Align effects-browser actions, bound long labels, improve search and scan feedback, and respect effects disabled in Plug-in Manager.

0.1.0-beta.14 2026-09-15

Stereo VST3 effect inserts and consistent dialog controls.

Added

  • Add ordered VST3 effect chains to each part and the master, with searchable selection, bypass, reorder, remove, and same-instance plug-in editors.
  • Save exact effect identities and captured states in .brn sessions, retaining unavailable effects for recovery or explicit bypass.
  • Apply part effects to freezes and stem exports, and master effects to full mixdowns, with latency compensation and a shared 30-second effect-tail cap.

Changed

  • Standardize buttons, dropdowns, fields, dialog headers, and close controls; improve audio-settings and export-dialog alignment and presentation.
  • Host each effect in a separate worker. Failed effects fall back to aligned dry audio, and audio rendering requires explicit Retry or Bypass.

Fixed

  • Discover VST3 plug-ins inside vendor subfolders while avoiding bundle internals and directory-symlink loops.
  • Stop and reprepare effect workers after structural plug-in changes so stale latency or bus layouts cannot continue processing.
  • Preserve coherent effect state across editor changes, saves, audio rebuilds, freezes, and exports.

Known limitations

  • Effect inserts support stereo VST3 components. AU effects, sends, routed sidechains, and inserts on shared instrument returns are not included.
  • Sessions containing effect inserts use a newer session schema; keep backups when exchanging projects with older Brano versions.
  • Installed-effect validation covers MuseFX 1.0.7 Simple EQ, Delay, and Reverb; it does not establish compatibility with every third-party effect or preset.

0.1.0-beta.4 2026-08-25

Multi-timbral VST3 instrument racks and Kontakt reliability release.

Added

  • Add opt-in shared VST3 instrument racks with explicit per-member MIDI channels, output buses, returns, exact plug-in classes, and persisted state.
  • Add rack editing and mixer controls, including conversion back to dedicated compatibility instances and actionable validation feedback.
  • Add deterministic multi-output fixture coverage and an owner Kontakt 7 acceptance matrix spanning live playback, state reload, offline rendering, freeze/export parity, editor coexistence, and crash recovery.

Changed

  • Integrate shared racks across live playback, session round-trips, freeze, export, worker admission, and fault isolation while retaining one dedicated instance per part as the default and compatibility fallback.
  • Reduce a validated three-part Kontakt workload from three plug-in workers to one shared worker; keep the feature experimental because CPU and thermal improvement were not established.
  • Pin native-rack to the disposable-probe teardown fix used by the release validation path.

Fixed

  • Give Kontakt cold-load, editor, state, render, cancellation, and recovery phases bounded, progress-aware handling without blocking the UI or audio callback.
  • Require explicit VST3 class identity at every shared-rack boundary and keep rejected or over-capacity racks from consuming return capacity or blocking unrelated assignments.
  • Reap failed, timed-out, and intentionally disposable VST3 helpers without allowing plug-in background teardown to terminate the host process.

0.1.0-beta.3 2026-08-24

VST3 lifecycle, thermal safety, and measured-capacity release.

Added

  • Add Audio Settings controls for output device and configuration, with the actual callback size, engine latency, and measured VST3 capacity.
  • Add allocation-free audio telemetry for callback load, deadlines, stream errors, active voices and workers, lifecycle state, and worker faults.
  • Add release-mode thermal, lifecycle, realtime, and crash/hang containment gates for representative one- and three-instrument VST3 workloads.

Changed

  • Adopt native-rack 0.6.0 and its crash-isolated worker interface for VST3 hosting.
  • Replace the static live-voice limit with fail-closed admission based on qualifying machine, device, and workload measurements; unprofiled or over-capacity routes use Freeze for prerendered playback.
  • Park audio and worker activity while stopped or naturally complete, retain callback-eligible tails while paused, and reuse compatible voices across rebuilds.
  • Honor bounded per-voice plugin tails and skip work that cannot contribute audible output while preserving required transport and event delivery.

Fixed

  • Restrict the shipping macOS renderer to Metal and remove non-Metal product backend paths.
  • Keep VST3 helper processes out of the macOS Dock and menu bar.
  • Restart playback from the beginning when Play is pressed after natural completion.
  • Repair private-dependency authentication and GTK development dependencies for manually triggered Linux CI.
